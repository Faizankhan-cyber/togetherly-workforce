# 1. PRODUCT VISION

The platform must solve these core problems:

- Finding the right employees for a project.
- Building balanced teams based on required skills.
- Explaining why particular employees are recommended.
- Identifying missing skills and recommending training.
- Detecting overloaded and underutilized employees.
- Simulating alternative team allocations before confirming decisions.
- Giving employees a personalized view of their assignments, workload, and development.

The application should feel like a premium enterprise SaaS product, not a generic admin dashboard.

## Core product differentiator

Build a flagship feature named:

**Togetherly Workforce Twin: Simulate. Compare. Optimize.**

The Workforce Twin allows managers to simulate different workforce allocation decisions, see their consequences, compare alternatives, and confirm the best feasible assignment.

This feature must be interactive and connected to the actual application data. It must not be a static illustration or a dashboard full of hardcoded numbers.

# 4. FLAGSHIP FEATURE: WORKFORCE TWIN

Build a dedicated Workforce Twin page with a polished interactive simulation interface.

## A. Configure the simulation

Allow managers to:
- Select an existing project or create one.
- Define required skills and proficiency expectations.
- Define team size, project duration, and staffing requirements.
- Review eligible employees and their current workloads.
- Generate an initial recommended team.

## B. Explainable matching engine

Create a maintainable matching service that evaluates employees using:
- Relevant skills and proficiency.
- Relevant experience.
- Availability.
- Existing workload and remaining capacity.
- Project requirements and staffing constraints.

If appropriate, use this initial configurable score model:

- Skills match: 50%.
- Relevant experience: 25%.
- Availability and workload suitability: 25%.

Document the weights and calculation method. Normalize scores consistently and handle missing information explicitly.

Use hard constraints for genuinely ineligible candidates, such as insufficient availability or exceeded capacity where the project requires it. Explain any exclusion to the manager.

Do not allow a high skill score to conceal an employee's capacity violation.

For each candidate, display:
- Overall match score.
- Skills match score.
- Experience score.
- Availability and workload score.
- Matching skills.
- Missing or insufficient skills.
- Current workload.
- Remaining capacity.
- Reasons for recommendation.
- Potential risks and trade-offs.

Do not describe a deterministic scoring algorithm as a trained AI model.

## C. Team composition and comparison

Allow managers to:
- Generate recommended teams.
- Add or remove candidates.
- Swap employees.
- Compare at least two alternative team configurations when enough candidates exist.
- Compare skill coverage, overall fit, availability, workload balance, and potential risks.
- See why the recommended team is preferable.

Provide a clear explanation when one team has stronger skills but worse availability, or when a more balanced team offers a better feasible allocation.

## D. Interactive what-if simulation

When a manager changes a proposed team:
- Recalculate relevant team metrics.
- Update skill coverage.
- Update projected workloads.
- Identify capacity violations.
- Update candidate and team scores where appropriate.
- Highlight changes from the previous configuration.

Show before-and-after comparisons.

Simulations must remain temporary until confirmed. Provide Reset, Discard, and Confirm Allocation actions.

## E. Confirm allocation

When a manager confirms an allocation:
- Update project membership.
- Update employee assignments.
- Update workload calculations.
- Update the employee dashboards.
- Update relevant analytics.
- Preserve the allocation across refresh.

Do not mutate the underlying assignment data during an unconfirmed simulation.
